# 金鉴真人体系 · 商业化架构改进方案
日期：2026-07-27
依据：两份 Hermes Agent 商业化架构方案文档 + 当前架构审计

════════════════════════════════════════════════════════════
## 一、核心诊断
════════════════════════════════════════════════════════════

### 当前架构的致命缺陷
```
当前工作方式（问题）：
  用户提问 → Agent收到 → Agent"决定"是否读SKILL.md/SOP → 
  Agent"决定"是否查知识库 → Agent输出 → 无校验

这个问题导致：Agent在超过80次调用后必然出现"遗忘"。
```

### 目标架构
```
改进后工作方式（确定性）：
  用户提问 → ①前置强检索（代码层无条件执行）
           → ②知识+SOP硬注入到上下文（Agent无法跳过）
           → ③Agent仅做推理（无搜索工具，无选择权）
           → ④输出校验门禁（不通过则驳回重做）
           → ⑤结果持久化 → 上下文重置
```

════════════════════════════════════════════════════════════
## 二、体系化改进方案（六层）
════════════════════════════════════════════════════════════

### 第1层：知识层 — 从"文本文件"升级为"向量数据库"

**现状**：SKILL.md 是纯文本文件，Agent通过Hermes的skill_view工具加载，
但每次加载依赖Agent"记得去查"。

**改进**：
1. 将 SKILL.md §35-§40 各章节拆分为独立的知识块
2. 存入向量数据库（Chroma 本地）
3. 每个知识块带 metadata 标记：
   - 所属章节（§35/§36/§37/§38/§39/§40）
   - 主题标签（喜忌/格局/墓库/分线断法等）
   - 适用场景（事业/财富/婚姻/健康/流年）

**代码实现**：
```python
# knowledge_base_builder.py
import chromadb
from chromadb.utils import embedding_functions

# 读取SKILL.md各章节，按"###"标题切块
# 每块存入Chroma，metadata标记章节+主题
# 供后续前置检索使用
```

### 第2层：前置检索层 — 从"Agent决定查不查"改为"代码强制查"

**现状**：Agent有`skill_view`工具，但可以选择不用。

**改进**：
1. 在每个任务进入Agent之前，写一个强制前置Hook
2. 根据任务类型（事业分析/健康分析/合参等），自动从向量库检索相关SOP
3. 将检索结果硬注入到System Prompt，标注为"【强制知识·不可跳过】"

```python
# pre_retrieval_hook.py
def prepare_agent_context(task_type: str, user_query: str) -> str:
    # 1. 根据任务类型确定需要加载哪些知识章节
    required_sections = get_required_sections(task_type)
    
    # 2. 从Chroma检索最相关的3-5个知识块
    results = chroma_collection.query(
        query_texts=[user_query],
        n_results=5,
        where={"section": {"$in": required_sections}}
    )
    
    # 3. 拼接成强制知识上下文
    knowledge_block = f"""
    【强制知识 -- 你必须严格遵循以下内容】
    {format_results(results)}
    【工作守则】
    1. 你无需自行检索知识库，以上已提供最新最准确的知识
    2. 你的唯一依据是以上知识，不得使用未提供的信息
    3. 严格按照SOP步骤推理
    """
    return knowledge_block
```

### 第3层：工作流引擎层 — 从"Agent自主Loop"改为"确定性状态图"

**现状**：Agent在一个大循环里自己做所有事（检索→推理→输出→校验都在Agent内）。

**改进**：用LangGraph定义每个场景的状态图：

```python
# workflow_engine.py
from langgraph.graph import StateGraph, END

# 以"八字分析"场景为例的状态图：
# [收到请求] → [前置检索]（代码层强制）
#            → [格局判断]（LLM节点·基于已注入知识）
#            → [喜忌推导]（LLM节点·基于已注入知识）
#            → [分线断法]（LLM节点·基于已注入知识）
#            → [校验门禁]（代码层校验·不通过则驳回）
#            → [输出]
```

每个Node是"确定性代码节点"或"LLM推理节点"，两者严格区分：
- 代码节点：检索、校验、数据转换（100%确定）
- LLM节点：推理、判断、写作（仅在此步骤使用LLM）

### 第4层：校验与护栏层 — 从"抽样验证"改为"全量硬性校验"

**现状**：`validate_analysis.py` 只做抽样验证（MingLi-Bench题库）。

**改进**：每步LLM输出后必过校验：

```python
# gatekeeper.py
from pydantic import BaseModel, Field

class AnalysisOutput(BaseModel):
    """强制LLM输出的JSON结构"""
    section: str = Field(description="当前分析章节名")
    sop_step_followed: str = Field(description="遵循的SOP步骤编号")
    knowledge_ref: str = Field(description="引用的知识来源（章节+条款）")
    conclusion: str = Field(description="分析结论")
    
def validate_output(output: dict, required_steps: list) -> tuple[bool, str]:
    """校验LLM输出是否符合SOP"""
    # 检查是否遵循了规定的步骤
    if output.get("sop_step_followed") not in required_steps:
        return False, f"未遵循规定步骤，应为{required_steps}之一"
    # 检查是否引用了注入的知识
    if not any(ref in output.get("knowledge_ref", "") for ref in ["§", "第"]):
        return False, "未引用提供的知识来源"
    return True, "通过"
```

### 第5层：上下文管理层 — 从"无管理"改为"每任务隔离"

**现状**：Agent的会话上下文会累积，导致"上个任务的惯性影响下个任务"。

**改进**：
1. 每个定时任务/API请求创建全新的Agent实例
2. 执行完毕后销毁上下文
3. 关键数据写盘持久化（不依赖LLM记忆）
4. 下一个任务重新加载知识，不被前一个任务污染

### 第6层：观测评估层 — 从"无观测"改为"全量追踪"

**现状**：无日志系统，错误只能靠用户反馈。

**改进**：
1. 记录每个任务的执行链：检索了什么知识→LLM输出了什么→校验通过与否
2. 建立Golden Dataset（典型输入+预期输出）
3. 每天自动评估准确率
4. 低于阈值则告警
